# Roadmap

Phases follow the audit ([PROJECT_AUDIT.md](PROJECT_AUDIT.md), §13). A phase is complete only when its acceptance criteria are verified. "Verified" below means the check was actually executed; the evidence is listed.

## Decisions approved on 2026-10-12

1. Foundation phase before the transfer engine.
2. Existing data is disposable. Switch from MySQL to **PostgreSQL** with a Flyway baseline (Docker for the stack, local pgAdmin database for development).
3. Token storage: HttpOnly cookie + CSRF (implemented in Phase 3).
4. Frontend tooling: **Vite**, staying in JavaScript.
5. Java 21 LTS and the current Spring Boot line (4.1).
6. `organization_id` in the baseline.
7. A currency per account; same-currency transfers only.
8. Clients may transfer to **any account** (by RIB).
9. RIBs are **generated by the server**.
10. Everything in **English**: code, enum values, role names (`AGENT_GUICHET` → `AGENT`), UI.

> **Correction (found in Phase 3):** the Docker "end-to-end" checks of Phases 1 and 2 used curl, which sends no `Origin` header. In a real browser, every POST through Nginx (including login) was rejected with `403 Invalid CORS request`, because Nginx forwarded `Host` without the port. Fixed in Phase 3 and verified with headless Chrome (ADR-008).

Not done in Phase 1 (by design, see Phase 2+): transfers, history, CSP, cookie-based tokens, rate limiting, password change, OpenAPI.
